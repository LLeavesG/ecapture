## Procedure

The Android binary was pushed to `/data/local/tmp/ecapture-jni` and started
before a force-stop and cold start of Doubao:

```sh
ecapture \
  --event-format=json \
  --eventaddr=/data/local/tmp/jni-conversion-events.jsonl \
  -l /data/local/tmp/jni-conversion.log \
  tls \
  --profile /data/local/tmp/art-profile-device.json
```

The profile was the ART Build-ID-pinned scaffold generated by
`ecapture profile inspect` and included both `register_natives_offsets` and
`conversion_offsets`.

The top modules prove two properties at once:

- The hook points are ART-build specific but app-agnostic. The same profile
  worked across framework, runtime, and Doubao libraries without private ART
  symbols.

  and caller-offset allowlist is still required before treating this as a
  semantic request/response extractor.

## Implications

- `RegisterNatives` plus standard conversion slots is enough to turn a cold
  start into a searchable native caller map.
- The current implementation is suitable as a diagnostic replacement for
  “Frida + hook JNI conversion + proxy” when the goal is to find where managed
  references become native bytes.
- It is not yet a direct mitmproxy replacement for request reconstruction.
  The remaining work is callsite reduction and protocol-aware grouping of the
  captured conversion, TLS, QUIC, and packet events.
